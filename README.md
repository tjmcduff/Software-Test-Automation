# Software-Test-Automation
1. How can I ensure that my code, program, or software is functional and secure?
Ensuring the functionality and security of a program requires a structured approach that includes various testing strategies. Throughout this course, I implemented unit testing using JUnit to verify that my ContactService and TaskService classes met the specified requirements. Assertions were used to validate constraints such as unique contact IDs, name length limits, and null value restrictions.

To ensure security, I followed best practices in exception handling, input validation, and modularization. By using boundary testing, I tested edge cases to prevent errors that could compromise the integrity of the program. Additionally, I used negative testing techniques to confirm that improper inputs were handled gracefully. These strategies help maintain the reliability, stability, and security of the software.

2. How do I interpret user needs and incorporate them into a program?
Interpreting user needs starts with understanding the requirements set forth at the beginning of the software development process. In my projects, I carefully reviewed specifications to ensure that key constraints were met, such as limiting the length of task descriptions and ensuring unique identifiers for contacts.

By implementing functional testing, I verified that each feature behaved as intended based on user expectations. Through a combination of static and dynamic testing methods, I ensured that the software met functional and performance requirements. Moreover, exception handling mechanisms were incorporated to enhance the user experience by preventing unexpected crashes and providing informative error messages.

3. How do I approach designing software?
My approach to software design follows structured principles that prioritize maintainability, efficiency, and correctness. I started by breaking down the project into modular components, such as ContactService, TaskService, and AppointmentService. Each module was designed with clear responsibilities, making the program easier to manage and test.

Incorporating test-driven development (TDD) principles, I wrote unit tests before implementing certain functionalities to ensure that my design met requirements from the outset. I optimized my code by reducing redundant operations, ensuring efficient data retrieval, and using concise test cases to validate multiple scenarios. Through systematic testing and validation, I was able to confirm that the design aligned with both functional requirements and best coding practices.
